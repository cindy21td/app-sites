Bitcue Chiptune Game Loops

Using Bitcue's cue files in your game

Bitcue writes a song as one loop in three intensities: Calm, Alert and Battle. This page is about getting those files into a game engine and switching between them on the bar line.

What you get

  • Free: one loop. On the Export sheet, choose This loop, pick Calm, Alert or Battle and tap Save to Files. You get one WAV, named after the song and the cue (for example lantern-cave-alert.wav).
  • Bitcue Pro: the matched set. Choose Matched set and Bitcue writes a folder named after the song, with 8 files: calm.wav, alert.wav and battle.wav; stems/calm.wav, stems/alert.wav and stems/battle.wav; cues.json; and a MIDI file named after the song.
  • The loops are full mixes: Alert contains everything in Calm plus the kick and snare, and Battle contains everything in Alert plus the lead. The stems are the opposite: each holds only what enters on that cue, so Calm + Alert stem + Battle stem adds up to Battle.
  • Every WAV is 16-bit mono, 44,100 Hz, with one forward loop over the whole file stored in the file's smpl chunk (sample 0 to the last sample).
  • cues.json holds the numbers your engine needs: tempo (BPM), beatsPerBar, bars, sampleRate and loopLengthSamples.

Why the cues line up

All three loops come from the same song, so they share one tempo and one bar grid, and every file is exactly the same length to the sample: bars × beatsPerBar × 60 ÷ tempo × 44,100, rounded once. The last notes of the loop are folded back into the start, so a loop repeats without a click.

Because of that, you can start Alert at the same playback position Calm has reached, or restart on the next bar line, and the music stays in time. Bar 1 of every file is the same bar.

A new song starts at 8 bars. Pro also writes 16 and 32 bar loops. Tempo runs from 40 to 200 BPM and beatsPerBar in cues.json gives the beats in each bar.

Working out the bar length

Read tempo and beatsPerBar from cues.json and compute:

barSeconds = beatsPerBar * 60 / tempo

At 120 BPM in 4/4 a bar is 2 seconds, and an 8 bar loop is 16 seconds. To switch on the next bar line, find how far into the loop the music is, and wait for the time left in that bar:

position   = music.currentTime            // seconds into the loop
wait       = barSeconds - (position % barSeconds)
at (now + wait): switch to the new cue

Take the position from the audio clock your engine plays the music on, not from frame time, so the switch does not drift.

Unity

  • Drag the WAV files into the Project window. In the import settings you can leave Load Type as Compressed In Memory or Streaming for music.
  • Unity does not read the loop points from the WAV, so tick Loop on the AudioSource that plays the cue.
  • Use one AudioSource per cue. Start all three with PlayScheduled on the same DSP time, and set the volume of Alert and Battle to 0 until needed. Or use the stems the same way, with one AudioSource per stem.
  • To switch, wait for the next bar line as above using AudioSettings.dspTime, then change which source is audible. With the full-mix loops, fade one out and the next in. With the stems, raise the next stem's volume.

Godot

  • Drop the WAV files into the project. In the Import dock, set Loop Mode to Detect From WAV (or Forward) and reimport.
  • For the stems, add an AudioStreamSynchronized with one stream per stem and raise a stem's volume to climb a cue. Play it from an AudioStreamPlayer.
  • For the three loops, use an AudioStreamInteractive with a clip for each cue. Set the transition between clips to start at Next Bar (TRANSITION_FROM_TIME_NEXT_BAR). The tempo and beats per bar in cues.json tell you where the bars fall if you need to check.

GameMaker

  • Add the WAV files as Sound assets.
  • GameMaker plays the file through, so loop it in code: audio_play_sound(snd_calm, 1, true) for a looping sound.
  • To switch on the bar line, keep a timer from the moment the loop started, work out the time left in the current bar as above, and when it runs out, start the next cue with audio_play_sound_ext at the position audio_sound_get_track_position reports for the current one, then stop the old one.

Other engines

Anything that can loop a WAV can play Bitcue loops. Load the three files, loop them, keep the same playback position across them, and switch when the bar time runs out. If you want to rebuild the song in your own tools, the MIDI file has a track per voice and cue, at the same tempo.
